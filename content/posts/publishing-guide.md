## 内容放在哪里

文章分为元信息与正文两部分。`content/posts.json` 保存标题、摘要、分类、标签、日期和作者；`content/posts/` 保存 Markdown 正文。文件名与文章的 `slug` 一致。

## 添加一篇文章

在文章列表中添加一条记录。短名使用小写英文字母、数字和连字符，发布后尽量保持不变。

```json
{
  "slug": "my-first-post",
  "title": "我的第一篇文章",
  "description": "一句话介绍文章讨论的问题。",
  "category": "随笔",
  "tags": ["写作"],
  "date": "2026-09-17",
  "author": "你的名字"
}
```

然后创建 `content/posts/my-first-post.md`。正文从二级标题开始，文章标题会由页面自动显示。分类和标签从文章数据自动汇总，没有固定数量要求。

## Markdown 排版

可以使用 **粗体**、*斜体*、`行内代码`、引用、列表、表格、链接和代码块。正文中的 HTML 会经过安全过滤，不支持脚本、事件处理器和嵌入页面。

### 图片

把图片放入 `public/images/`，用 Markdown 引用，例如 `![有意义的图片说明](/images/example.webp)`。图片说明应描述信息本身，不要只写“图片”。

### 文章之间的链接

使用 `#/post/文章短名` 链接到其他文章。例如：[设计笔记](#/post/reading-and-motion)。它可以在普通静态托管中直接访问，无需服务器配置路径重写。

## 检查与发布

```bash
npm run check:blog
npm run build
```

内容检查会拒绝重复短名、缺失正文、无效日期和缺失的必填字段。构建产物位于 `dist`，可以部署到支持静态文件的服务。现有 Cloudflare 打包命令仍然可用。

## 替换示例

本站默认附带的是说明用途的示例文章，不代表站点所有者的经历或观点。准备发布自己的博客时，可以删除或替换这些文件；不要把文章数量补足为原三维阵列的数量，两者已经独立。
