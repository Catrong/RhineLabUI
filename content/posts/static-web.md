## 内容是最值得保留的部分

框架会升级，托管服务会改变，但纯文本内容很容易迁移。把正文保存在 Markdown 文件中，把元信息放在清楚的结构里，可以减少长期维护的不确定性。

## 构建时发现问题

重复地址、不存在的正文和错误的日期，都适合在发布之前检查。失败应有具体原因，而不是上线之后留给读者一个空白页面。

```text
内容文件 → 校验 → 构建 → 静态资源 → 浏览器
```

## 离线与更新

离线缓存可以让已经下载的文章继续阅读。新版本应完整下载后再切换，不能把旧页面与新资源随意混用。收藏和阅读偏好属于读者，不应随着更新被清空。

## 保持简单

评论、统计、全文索引服务都有价值，但不必一次接入。先让写作、查找和阅读形成完整路径，再根据真实使用决定下一项投入。
